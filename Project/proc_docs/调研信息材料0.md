## 一、VIO核心算法选型

### 1.1 基座VIO框架 - 已有信息

#### UL-VIO (ECCV 2024)

| 项目 | 详情 |
|:----|:------|
| GitHub | <https://github.com/jp4327/ulvio> |
| Stars/Forks | 34 / 5 (非常少, 社区不活跃) |
| 最后更新 | 2024年10月 |
| 代码语言 | Python + PyTorch |
| 代码规模 | ULVIO.py约200行, layers.py约100行, test.py约100行 |
| 预训练模型 | 已提供 model_ulvio_v1.pth (3.6MB) |
| 依赖 | PyTorch 2.4.1 + torchvision + matplotlib + numpy |
| 是否需要ROS | 不需要 - 纯Python实现 |
| 参数量 | <1M |
| 架构 | VisualEncoder(6层CNN) + InertialEncoder(3层Conv1d) + PoseMLP(2层MLP) |
| 输入 | 连续图像帧 + IMU数据序列 |
| 输出 | 6自由度位姿 (tx, ty, tz, rx, ry, rz) |
| 训练方式 | 监督学习 (需要真值位姿标签) |
| 是否需要GPU | 是 (CUDA) |

**判断**: UL-VIO代码简洁、纯Python、不依赖ROS、有预训练模型, 非常适合作为基座。但stars少说明用的人不多, 可能遇到坑需要自己填。

#### UL-VIO现有VisualEncoder架构

```
Conv1: 6 -> 8, k=5, s=2
Conv2: 8 -> 16, k=3, s=2
Conv3: 16 -> 64, k=5, s=2
Conv4: 64 -> 64, k=3, s=2
Conv4_1: 64 -> 64, k=3, s=1
Conv5: 64 -> 192, k=3, s=2
Conv5_1: 192 -> 64, k=3, s=1  (这里降维了)
Conv6: 64 -> 256, k=3, s=2
AdaptiveAvgPool -> Linear(256, 256)
```

非常浅的CNN, 改进空间很大。

### 1.3-1.5 其他算法细节

**IALM光照自适应模块**: IBN-Net (Instance-Batch Normalization) 有开源PyTorch实现, 可以借鉴。

**Filter-wise Pruning**: PyTorch官方提供 torch.prune 工具, TensorRT支持通道剪枝。

**IMU偏置校准**: UL-VIO的InertialEncoder使用3层Conv1d处理IMU数据, 没有显式的偏置校准模块。UL-VIO论文中提出了一种基于视觉-惯性一致性的测试时自适应(TTA)机制。

#### 火星数据

| 数据源 | 可用性 | 说明 |
|:------|:------|:-----|
| HiRISE (NASA) | 公开 | 高分辨率单张影像, 无IMU/连续帧 |
| MRO CTX | 公开 | 中分辨率火星影像 |

**关键问题**: 没有现成的火星表面连续图像+IMU序列。需要自己用仿真器生成, 或用地球类火星场景替代。

#### MADMAX数据集 (火星车VIO专用数据集)

| 项目 | 详情 |
|:----|:------|
| **全称** | Morocco-Acquired data set of Mars-Analog eXploration (MADMAX) |
| **论文** | Journal of Field Robotics, 2021 (DOI: 10.1002/rob.22016, 被引62次) |
| **作者** | Lukas Meyer, Michal Smisek (DLR德国宇航中心) 等12人 |
| **数据集网址** | <https://rmc.dlr.de/morocco2018>  可访问 |
| **数据集内容** | 在摩洛哥沙漠(火星类比环境)采集的视觉+惯性数据 |

| **真值** | RTK-GPS融合双天线GNSS数据, 提供位置+姿态+不确定性 |

| **引用论文** | 已被62篇论文引用, 包括月球导航SLAM、多传感器SLAM数据集等工作 |
| **对项目的意义** |  这是**唯一公开的火星类比环境VIO数据集**, 比EuRoC/TUM VI更贴合项目背景 |
| **是否需要仿真替代** | 如果使用MADMAX, 可部分降低对火星场景仿真的依赖 |

| 序列 | 场景描述 | VINS-Mono (ATE) | ORB-SLAM3 VI (ATE) |

## 四、初步建议方向

基于调研信息, 推荐的技术方案候选方向:

- **基座框架**: UL-VIO (保留其轻量骨架, 替换视觉前端)
- **视觉前端**: 从SuperPoint+SuperGlue思路出发做轻量化改进, 或设计<3M参数的轻量匹配网络
- **光照处理**: IBN-Net层或数据增强, 实现简单
- **轻量化**: PyTorch剪枝 + TensorRT INT8量化
- **数据集**: EuRoC为主 + TUM VI为辅
- **仿真**: Gazebo火星场景 (利用现有GitHub资源)
- **边缘设备**: Jetson Orin Nano 8GB (预算范围内)
- **精度目标**: 在EuRoC上达到或接近VINS-Mono水平 (ATE < 0.15m)
